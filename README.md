# 内测批量续卡 Skill

`internal-test-batch-renewal` 用于把门店原始签到记录 Excel 清洗后，先列出实际出现的卡项并向用户确认逐卡续卡规则，再生成可导入后台的批量续卡 Excel。适合香蕉攀岩门店在内测、试营业或活动结束后，为符合条件的会员统一续期或加次。

## 适用场景

适合以下工作：

- 门店内测结束后，根据签到记录为参与用户统一续卡。
- 不确定原始表中有哪些卡项，需要先盘点卡项和用户卡数量。
- 不同卡项需要分别设置新增天数和新增次数。
- 将用户卡 ID、成员姓名、手机号码和卡项类别自动填入批量续卡模板。
- 同一卡项用户需要归类排列，并对重复用户卡 ID 做检查和去重。
- 输出文件需要在导入后台前完成字段、续卡值和数据完整性校验。

不适合以下工作：

- 只对普通签到表进行排序、标色或统计。
- 清洗与续卡无关的会员资产数据。
- 使用模糊匹配、包含匹配或关键词猜测卡项。
- 处理 `.xls`、`.csv` 等非 `.xlsx` 源文件。
- 给未明确列入目标卡项的用户续卡。

## 主要功能

1. 自动寻找同时包含以下字段的工作表：
   - `用户卡ID`
   - `成员姓名`
   - `手机号码`
   - `签到卡` 或 `签到卡类`
2. 第一阶段只读清洗数据，忽略空白及 `-` 等无卡项占位行，列出每个真实卡项的出现行数和唯一用户卡 ID 数。
3. 等待用户确认需要续卡的卡项，以及各卡项的新增天数、新增次数和续卡原因。
4. 按用户确认的完整卡项名称精确匹配，不使用模糊匹配。
5. 按用户确认的卡项顺序分组排列，同一卡项用户会排在一起；组内保留源表顺序。
6. 使用 `用户卡ID` 去重：
   - 完全重复的数据只保留第一条。
   - 同一用户卡 ID 对应不同卡项、姓名或手机号时停止处理并报告冲突。
7. 自动套用仓库内的批量续卡模板。
8. 导出后重新打开 Excel，检查记录数、字段完整性、逐卡规则、重复 ID、公式错误和其他工作表是否被改动。
9. 可生成顶部、卡项分组交界处和底部三张预览图，供 Agent 做视觉检查。

## 续卡规则

每个被选中的卡项都可以单独设置规则。例如：

| 卡项 | 新增天数 | 新增次数 | 说明 |
| --- | ---: | ---: | --- |
| 月卡 | 1 | 0 | 有效期增加 1 天 |
| 10次卡 | -1 | 1 | 增加 1 次，并清空结束时间，设为永久有效 |

规则值必须是整数。新增天数不能小于 `-1`，新增次数不能小于 `0`，两者不能同时为 `0`。

> 用户要求次卡永久有效时，`新增天数` 必须填写 `-1`，不能填写 `0`。否则已经到期或次数已用完的次卡，续卡后可能仍无法正常使用。

## 输出字段

生成文件的主表固定包含以下列：

1. `用户卡ID`
2. `成员姓名`
3. `手机号码`
4. `卡项类别`
5. `新增天数`
6. `新增次数`
7. `续卡原因`

用户卡 ID 和手机号码按文本写入，避免长数字被转换成科学计数法；源表中的脱敏姓名或手机号会原样保留。

## 在 Codex 中使用

### 1. 提供原始签到记录

把原始签到记录 `.xlsx` 交给 Agent，并说明使用本 skill：

```text
使用 $internal-test-batch-renewal 清洗这份签到记录，并列出表格里实际出现的卡项。
```

### 2. Agent 盘点卡项

Agent 会先清洗数据，不会立即生成续卡表。它会返回类似结果：

```text
卡项                         出现行数   唯一用户卡数
月卡                         86         84
季卡                         22         22
10次卡                       31         30
杭州开城预售•二十次卡        12         12
```

同时报告重复行、缺失字段和冲突 ID。然后 Agent 会询问需要续卡的卡项与规则。

### 3. 用户确认续卡规则

按下面格式回复：

```text
月卡：新增天数 1，新增次数 0
季卡：新增天数 2，新增次数 0
10次卡：新增天数 -1，新增次数 1
续卡原因：杭州来福士内测续卡。
```

用户没有选择的卡项不会写入最终表格。若首次请求已经包含完整的逐卡规则和续卡原因，Agent 可以跳过反问。

### 4. Agent 生成最终 Excel

Agent 会按确认顺序筛选、分组、去重、填入模板并校验，最终只交付一份可导入的 `.xlsx` 文件，同时报告每个卡项的记录数和去重数量。

## 直接运行脚本

通常应由 Codex 调用本 skill。需要手动运行时，先取得 Codex 工作区提供的 Node.js 和 `node_modules` 路径。

第一阶段只读盘点：

```bash
"<node_path>" scripts/build_batch_renewal.mjs \
  --mode inspect \
  --node-modules "<node_modules_path>" \
  --source "/absolute/path/签到记录.xlsx"
```

脚本会输出 JSON，其中包含全部卡项、出现行数、唯一用户卡 ID 数、重复数和异常。

用户确认后，建立规则文件：

```json
{
  "rules": [
    { "card": "月卡", "days": 1, "times": 0 },
    { "card": "10次卡", "days": -1, "times": 1 }
  ]
}
```

第二阶段生成 Excel：

```bash
"<node_path>" scripts/build_batch_renewal.mjs \
  --mode build \
  --node-modules "<node_modules_path>" \
  --source "/absolute/path/签到记录.xlsx" \
  --output "/absolute/path/outputs/内测批量续卡.xlsx" \
  --reason "10.1悠方店内测续卡" \
  --rules-json "/absolute/path/work/renewal-rules.json" \
  --preview-dir "/absolute/path/work/previews"
```

兼容旧版固定规则时，可以不传 `--rules-json`，并选择性覆盖默认卡项：

```bash
--duration-cards "新人月卡,月卡,季卡,年卡" \
--count-cards "10次卡,20次卡"
```

使用其他模板时追加：

```bash
--template "/absolute/path/批量续卡模板.xlsx"
```

### 参数说明

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `--mode` | 否 | `inspect` 只读盘点；`build` 生成 Excel，默认为 `build` |
| `--node-modules` | 是 | 包含 `@oai/artifact-tool` 的工作区依赖路径 |
| `--source` | 是 | 原始签到记录 `.xlsx` 的绝对路径 |
| `--output` | build 时必填 | 输出 `.xlsx` 的绝对路径 |
| `--reason` | build 时必填 | 写入每一行的续卡原因 |
| `--rules-json` | 推荐 | 用户确认后的逐卡规则 JSON 路径 |
| `--preview-dir` | 否 | 预览图片输出目录 |
| `--duration-cards` | 兼容模式 | 旧版逗号分隔期限卡名称，固定使用 `1 / 0` |
| `--count-cards` | 兼容模式 | 旧版逗号分隔次卡名称，固定使用 `-1 / 1` |
| `--template` | 否 | 自定义续卡模板路径；不填则使用仓库内模板 |

## 处理失败时

遇到以下情况时，skill 会停止而不是生成可能错误的续卡文件：

- 找不到必需的源表字段。
- 目标用户缺少用户卡 ID、成员姓名或手机号码。
- 同一用户卡 ID 出现信息冲突。
- 没有任何记录精确命中用户确认的卡项。
- 规则文件缺少卡项、包含重复卡项或使用无效的天数/次数。
- 导出后的记录数、续卡值或模板内容校验失败。
