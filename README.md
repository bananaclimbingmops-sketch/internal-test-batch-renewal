# 内测批量续卡 Skill

`internal-test-batch-renewal` 用于把门店原始签到记录 Excel 自动整理成可导入后台的批量续卡 Excel，适合香蕉攀岩门店在内测、试营业或活动结束后，为符合条件的会员统一续期或加次。

## 适用场景

适合以下工作：

- 门店内测结束后，根据签到记录为参与用户统一续卡。
- 从签到记录中筛选指定期限卡，为每张卡续期 1 天。
- 从签到记录中筛选指定次卡，为每张卡增加 1 次，并设为永久有效。
- 将用户卡 ID、成员姓名、手机号码和卡项类别自动填入批量续卡模板。
- 同一卡项用户需要归类排列，并对重复用户卡 ID 做检查和去重。
- 输出文件需要在导入后台前完成字段、续卡值和数据完整性校验。

不适合以下工作：

- 只对普通签到表进行排序、标色或统计。
- 清洗与续卡无关的会员资产数据。
- 使用模糊匹配、包含匹配或关键词猜测卡项。
- 处理 `.xls`、`.csv` 等非 `.xlsx` 源文件。
- 给未明确列入目标卡项的用户续卡。

## 主要功能

1. 自动寻找同时包含以下字段的工作表：
   - `用户卡ID`
   - `成员姓名`
   - `手机号码`
   - `签到卡` 或 `签到卡类`
2. 按卡项名称进行完全匹配，忽略首尾空格，但不会使用模糊匹配。
3. 默认处理以下卡项：
   - 期限卡：`新人月卡`、`月卡`、`季卡`、`年卡`
   - 次卡：`10次卡`、`20次卡`
4. 按卡项顺序分组排列，同一卡项用户会排在一起；组内保留源表顺序。
5. 使用 `用户卡ID` 去重：
   - 完全重复的数据只保留第一条。
   - 同一用户卡 ID 对应不同卡项、姓名或手机号时停止处理并报告冲突。
6. 自动套用仓库内的批量续卡模板。
7. 导出后重新打开 Excel，检查记录数、字段完整性、续卡规则、重复 ID、公式错误和其他工作表是否被改动。
8. 可生成顶部、期限卡与次卡交界处、底部三张预览图，供 Agent 做视觉检查。

## 续卡规则

| 卡项类别 | 新增天数 | 新增次数 | 说明 |
| --- | ---: | ---: | --- |
| 期限卡 | 1 | 0 | 有效期增加 1 天 |
| 次卡 | -1 | 1 | 增加 1 次，并清空结束时间，设为永久有效 |

> 次卡的 `新增天数` 必须填写 `-1`，不能填写 `0`。否则已经到期或次数已用完的次卡，续卡后可能仍无法正常使用。

## 输出字段

生成文件的主表固定包含以下列：

1. `用户卡ID`
2. `成员姓名`
3. `手机号码`
4. `卡项类别`
5. `新增天数`
6. `新增次数`
7. `续卡原因`

用户卡 ID 和手机号码按文本写入，避免长数字被转换成科学计数法；源表中的脱敏姓名或手机号会原样保留。

## 在 Codex 中使用

### 1. 准备文件和信息

向 Agent 提供：

- 原始签到记录 `.xlsx`
- 本次续卡原因，例如：`10.1悠方店内测续卡`
- 如需覆盖默认范围，明确列出期限卡和次卡名称

### 2. 调用 Skill

默认卡项可直接这样说：

```text
使用 $internal-test-batch-renewal 处理这份签到记录。
期限卡续期 1 天，次卡增加 1 次并永久有效。
续卡原因：10.1悠方店内测续卡。
```

自定义卡项可这样说：

```text
使用 $internal-test-batch-renewal 处理这份签到记录。
期限卡：新人月卡、月卡、季卡、年卡。
次卡：10次卡、20次卡、杭州开城预售•十次卡、杭州开城预售•二十次卡。
续卡原因：杭州来福士内测续卡。
```

Agent 会筛选、分组、去重、填入模板并校验，最终只交付一份可导入的 `.xlsx` 文件，同时报告期限卡数量、次卡数量和去重数量。

## 直接运行脚本

通常应由 Codex 调用本 skill。需要手动运行时，先取得 Codex 工作区提供的 Node.js 和 `node_modules` 路径，然后执行：

```bash
"<node_path>" scripts/build_batch_renewal.mjs \
  --node-modules "<node_modules_path>" \
  --source "/absolute/path/签到记录.xlsx" \
  --output "/absolute/path/outputs/内测批量续卡.xlsx" \
  --reason "10.1悠方店内测续卡" \
  --preview-dir "/absolute/path/work/previews"
```

覆盖默认卡项：

```bash
--duration-cards "新人月卡,月卡,季卡,年卡" \
--count-cards "10次卡,20次卡"
```

使用其他模板时追加：

```bash
--template "/absolute/path/批量续卡模板.xlsx"
```

### 参数说明

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| `--node-modules` | 是 | 包含 `@oai/artifact-tool` 的工作区依赖路径 |
| `--source` | 是 | 原始签到记录 `.xlsx` 的绝对路径 |
| `--output` | 是 | 输出 `.xlsx` 的绝对路径 |
| `--reason` | 是 | 写入每一行的续卡原因 |
| `--preview-dir` | 否 | 预览图片输出目录 |
| `--duration-cards` | 否 | 逗号分隔的期限卡完整名称 |
| `--count-cards` | 否 | 逗号分隔的次卡完整名称 |
| `--template` | 否 | 自定义续卡模板路径；不填则使用仓库内模板 |

## 处理失败时

遇到以下情况时，skill 会停止而不是生成可能错误的续卡文件：

- 找不到必需的源表字段。
- 目标用户缺少用户卡 ID、成员姓名或手机号码。
- 同一用户卡 ID 出现信息冲突。
- 没有任何记录精确命中目标卡项。
- 期限卡和次卡列表中出现相同卡项。
- 导出后的记录数、续卡值或模板内容校验失败。
